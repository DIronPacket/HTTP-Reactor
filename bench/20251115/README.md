# 今日优化
* 使用spdlog高性能异步日志库替换原本的自定义I/O日志记录
* 在HTTP消息处理中，fd的add和delete时添加互斥锁，防止线程争抢
# 优化结果：
| 指标 (Metric) | 20251113 | 20251115 | 变化分析 |  
| :--- | :--- | :--- | :--- |  
| **吞吐量 (Requests/sec)** | **1127.20** | **2504.67** | **20251115 吞吐量是 20251113 的 2.22 倍**。这是最核心的差距，意味着在相同时间内，无加密的 20251115 服务处理的请求数是加密的 20251113 服务的两倍还多。 |  
| **平均延迟 (Avg Latency)** | **353.74ms** | **191.32ms** | **20251113 的平均延迟几乎是 20251115 的两倍 (1.85倍)**。这意味着每个请求的平均响应时间，20251113 要慢得多。 |  
| **最大延迟 (Max Latency)** | **1.98s** | **733.06ms** | **20251113 的最大延迟非常高**，接近2秒，而 20251115 的最大延迟控制在1秒以内。这表明在高负载下，20251113 连接的“最坏情况”要严重得多。 |  
| **延迟标准差 (Stdev)** | **176.68ms** | **50.51ms** | **20251113 的延迟标准差是 20251115 的 3.5 倍**。这是一个非常关键的指标！它说明 20251113 的响应时间非常**不稳定**，波动极大。有的请求快，有的请求慢得离谱。而 20251115 的响应时间则稳定得多。 |  
| **总完成请求数** | 33,839 | 75,344 | 与吞吐量一致，30秒内 20251115 完成的请求数是 20251113 的两倍以上。 |  
| **数据传输率 (Transfer/sec)**| 83.66KB | 185.89KB | 同样，20251115 的数据传输率也远高于 20251113。 |
